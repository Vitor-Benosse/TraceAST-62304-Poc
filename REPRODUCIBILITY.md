This document describes the engineering controls implemented to ensure that all analyses, metrics, and reports generated by **TraceAST-62304** can be exactly reproduced by scientific peer reviewers and software quality teams.

---

## 1. Implemented Reproducibility Controls

Every execution of `python -m traceast scan` automatically generates `run_manifest.json` containing:

1. **System Version:** `TraceAST-62304 v1.0.0`.
2. **Exact Python Interpreter Version:** Recorded via `sys.version`.
3. **Target Repository Commit SHA:** Extracted from `.git/HEAD` when available.
4. **Rule Catalog SHA-256 Hash (`rule_catalog_sha256`):** Canonical cryptographic hash covering all definitions of rules `R01`–`R08`.
5. **SHA-256 Hashes of All Inspected Python Files:** Individually recorded in `repository_inventory.json`.
6. **SHA-256 Hashes of All Regulatory Documents Used in RAG:** Recorded in both `run_manifest.json` and `retrieval_trace.json`.
7. **Embedding Model and Retrieval Backend Identification:** Model name, revision, and active retrieval mode recorded.
8. **External LLM Audit Log:** Records whether external calls occurred, provider, model, parameters (`temperature`, `max_tokens`), consumed tokens, and elapsed time.
9. **Per-Stage Execution Durations:** Wall-clock times in seconds for AST/inventory, rules engine, RAG, LLM, and total pipeline.

## 2. Clean-Room Execution Procedure

### Step 1: Create an Isolated Virtual Environment

On Windows PowerShell:
```powershell
python -m venv venv_clean
.\venv_clean\Scripts\Activate.ps1
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
```

On Linux / macOS:
```bash
python3 -m venv venv_clean
source venv_clean/bin/activate
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
```

### Step 2: Verify Tool Version and Rule Catalog Hash

```bash
python -m traceast version
```

### Step 3: Execute the Full Automated Test Suite

```bash
python -m pytest -v
```

### Step 4: Build the Local RAG Index and Run a Deterministic Analysis

```bash
python -m traceast build-rag --docs-dir ./legal_documents --persist-dir ./db_regulacao_v1
python -m traceast scan --repo ./tests/fixtures/repo_well_structured --profile ./product_profile.example.yaml --out ./reports/repro_check
```

### Step 5: Generate Scientific Evaluation Artifacts

```bash
python -m traceast evaluate --out ./evaluation_artifacts
```

## 3. Artifacts to Preserve for JMIR Medical Informatics Submission

To ensure full scientific auditability of the manuscript, preserve and archive in a supplementary repository (e.g., Zenodo / OSF):

1. The frozen source code package including `requirements.txt` and `RULE_CATALOG.md` / `RULE_CATALOG.pt-br.md`.
2. The `evaluation_artifacts/dataset_split_manifest.json` file with the exact commit SHAs of all evaluated repositories.
3. For each evaluated repository, the complete output directory containing:
   - `findings.json`
   - `report.md`
   - `run_manifest.json`
   - `repository_inventory.json`
   - `retrieval_trace.json`
   - `analysis_metrics.json`
4. The original annotation sheets completed separately by Reviewer 1, Reviewer 2, Adjudicator 3, and the final Consensus sheet.
5. The statistical comparison JSON output (TP, FP, FN, TN, Precision, Recall, F1, 95% CI via *cluster bootstrap*, and *Cohen's kappa*) alongside `rag_recall_at_3_evaluation.json`.
